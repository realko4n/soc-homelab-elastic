# 01. Развертывание инфраструктуры и установка Elastic Stack

## 1. Подготовка виртуальной среды (Oracle VirtualBox)
Для лабораторного полигона выделены ресурсы на базе хост-машины (AMD Ryzen 7 5700X, 32 GB RAM):
* **Ubuntu Server 24.04.1 LTS** — выделено 4 ядра CPU, 8 ГБ ОЗУ, 50 ГБ виртуального диска. Сетевой адаптер переведен в режим **Сетевой мост (Bridged Adapter)** для прямого взаимодействия между узлами стенда.
* **Настройка статического IP-адреса:** чтобы избежать смены адреса по DHCP после перезагрузки и поломки SSL-сертификатов / маршрутизации агентов, в конфигурации Netplan (`/etc/netplan/50-cloud-init.yaml`) отключен `dhcp4` и жестко закреплен статический адрес **`192.168.1.206/24`** (шлюз `192.168.1.1`, DNS `8.8.8.8`, `1.1.1.1`).
* **Windows 10 Pro (22H2)** — развернута с локальной учетной записью, установлены гостевые дополнения (*Guest Additions*), Сетевой адаптер переведен из режима NAT в **Сетевой мост (Bridged Adapter)**, через PowerShell (`New-NetIPAddress` / `Set-DnsClientServerAddress`) закреплен статический адрес **`192.168.1.207/24`** (шлюз `192.168.1.1`, DNS `8.8.8.8`, `1.1.1.1`) и проверена связность с SIEM-сервером (`192.168.1.206`). Создан снимок состояния (*Snapshot*) для быстрого отката после тестов.

## 2. Установка Elasticsearch 9.5.7
Развертывание выполнено из официального дистрибутива (`.tar.gz`) в директорию `/opt/elasticsearch` от имени непривилегированного пользователя.

### Ключевые настройки (`/opt/elasticsearch/config/elasticsearch.yml` и `jvm.options.d/heap.options`):
* Ограничен размер кучи JVM (Heap Size) до 4 ГБ (`-Xms4g`, `-Xmx4g`) для стабильной работы в рамках 8 ГБ ОЗУ.
* Увеличен системный лимит виртуальной памяти ядра Linux: `sysctl -w vm.max_map_count=262144`.
* Открыт сетевой интерфейс (`network.host: 0.0.0.0`) для приема логов от внешних агентов.
* Настроена встроенная аутентификация (TLS/SSL) и сброшен пароль суперпользователя `elastic`.

## 3. Установка и настройка Kibana 9.5.7
Веб-интерфейс развернут в `/opt/kibana` и связан с узлом Elasticsearch с помощью *Enrollment Token*.

### Решенные технические задачи при настройке:
* **Сетевой доступ:** в `kibana.yml` задан параметр `server.host: "0.0.0.0"` для доступа к веб-интерфейсу по порту `5601`.
* **Настройка шифрования для плагина Fleet:** при запуске Kibana 9.5.7 плагин Fleet выдавал ошибку `503 Service Unavailable (FleetEncryptedSavedObjectEncryptionKeyRequired)`. Проблема решена генерацией и добавлением статических ключей шифрования (`xpack.encryptedSavedObjects.encryptionKey`, `xpack.reporting.encryptionKey`, `xpack.security.encryptionKey`) в конфигурационный файл `kibana.yml`.

## 4. Результат
* Кластер Elasticsearch запущен и принимает соединения по порту `9200`.
* Веб-интерфейс Kibana доступен по адресу `http://192.168.1.206:5601`, выполнена успешная авторизация.
* Создан снимок состояния (Snapshot) виртуальной машины в рабочем состоянии.
* Настроены системные юниты `systemd` (`/etc/systemd/system/elasticsearch.service` и `kibana.service`) для автоматического запуска стека после перезагрузки ОС и контроля лимитов файловых дескрипторов (`LimitNOFILE=65535`).
